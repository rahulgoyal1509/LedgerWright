## `POST /ingest/{source}`

Scan stage only — parses and normalizes a single file without matching it against anything.

**Path parameter**

| Name | Values |
|---|---|
| `source` | `bank` or `ledger` |

**Body** — `multipart/form-data`

| Field | Type | Notes |
|---|---|---|
| `file` | file | `.csv`, `.xlsx`, `.xls`, or `.pdf` |

**Example request**
```bash
curl -X POST http://127.0.0.1:8000/ingest/ledger \
  -F "file=@ledger.csv"
```

**Example response `200`** *(truncated to one transaction)*
```json
{
  "source": "ledger",
  "filename": "ledger.csv",
  "row_count": 25,
  "transactions": [
    {
      "source": "ledger",
      "source_id": "L001",
      "date": "2025-08-01",
      "description": "Rent Payment - August",
      "amount": 25000.0,
      "reference": "RENT-AUG25"
    }
  ]
}
```

**Error response `400`** — unsupported file type
```json
{"detail": "Unsupported file type '.txt'. Use CSV, XLSX, or PDF."}
```

**Error response `422`** — file failed to parse (e.g. missing required columns)
```json
{"detail": "Failed to parse <filename>: <underlying error>"}
```

## `POST /reconcile`

The full pipeline: Scan → Prematch → Triage → Verify → completeness audit. Returns every matched pair, every flagged item, and a health report.

**Body** — `multipart/form-data`

| Field | Type | Required | Notes |
|---|---|---|---|
| `ledger_file` | file | Yes | `.csv`, `.xlsx`, `.xls`, or `.pdf` |
| `bank_file` | file | Yes | `.csv`, `.xlsx`, `.xls`, or `.pdf` |
| `max_timing_lag_days` | int | No | Override the default (10) |
| `rounding_abs_tolerance` | float | No | Override the default (1.0) |
| `rounding_pct_tolerance` | float | No | Override the default (0.005) |

**Example request**
```bash
curl -X POST http://127.0.0.1:8000/reconcile \
  -F "ledger_file=@ledger.csv" \
  -F "bank_file=@bank_statement.csv"
```

### Response field reference

**`MatchResult`**

| Field | Type | Notes |
|---|---|---|
| `ledger_txn` | object \| null | Null if this result is a bank-only item |
| `bank_txn` | object \| null | Null if this result is a ledger-only item |
| `status` | `"auto_matched"` \| `"needs_review"` \| `"unmatched"` | |
| `category` | `"exact_match"` \| `"timing_lag"` \| `"rounding_difference"` \| `"duplicate_entry"` \| `"missing_entry"` \| `"genuine_error"` \| `"unknown"` | |
| `confidence` | float, 0.0–1.0 | 1.0 for exact matches; lower for AI-triaged or heuristic classifications |
| `explanation` | string | Plain-English reason, shown directly in the dashboard |

**`health`**

| Field | Notes |
|---|---|
| `complete` | `true` only if every ledger AND bank transaction ended up matched or flagged — nothing dropped |
| `matched_pair_balance_diff` | Sum of absolute differences across all auto-matched pairs — should be small (rounding-only) |
| `downgraded_on_verify` | Count of matches that failed re-verification and were sent back to review. Should be `0` in a healthy run |
| `config` | The actual thresholds used for this run (defaults or your overrides) |

## `POST /reconcile/report`

Identical pipeline and identical request body to `/reconcile`, but returns a downloadable `.xlsx` file instead of JSON.

**Example request**
```bash
curl -X POST http://127.0.0.1:8000/reconcile/report \
  -F "ledger_file=@ledger.csv" \
  -F "bank_file=@bank_statement.csv" \
  -o report.xlsx
```

**Response `200`**
Binary `.xlsx`, `Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`, filename `LedgerWright_Reconciliation_Report.xlsx`. Three sheets: `Summary`, `Auto-Matched`, `Flagged for Review`.

## Notes for Frontend/Integration Use

- CORS is currently open (`allow_origins=["*"]`) — fine for a hackathon demo, should be tightened to your actual frontend origin before any real production use.
- There's no authentication on any endpoint. Also fine for a hackathon demo; would need to be added before handling real financial data.
- File size limits are whatever your hosting platform's default is — not explicitly configured in the app itself.
